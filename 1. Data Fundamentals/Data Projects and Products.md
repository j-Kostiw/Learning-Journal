Key Concepts

Modern data engineering projects are:

dynamic,
iterative,
exploratory,
and constantly evolving.

Traditional linear project methods struggle because:

requirements change rapidly,
new data sources appear,
stakeholder priorities evolve,
real-time systems require flexibility.

Data engineers must therefore manage:

performance,
scalability,
reliability,
and continuous delivery of value.
Why Traditional Waterfall Struggles

Waterfall follows sequential phases:

Requirements
Design
Development
Testing
Deployment

Challenges include:

rigid requirements,
slow delivery,
delayed feedback,
resistance to change,
difficulty handling complex data ecosystems.
Data Engineering Problem

In data projects:

schemas evolve,
pipelines change,
APIs update,
data quality issues emerge unexpectedly.

This makes fixed long-term planning difficult.

Agile as a Data-Centric Approach

Agile supports:

adaptability,
iterative delivery,
collaboration,
faster feedback,
incremental value creation.

Benefits include:

ongoing visibility,
reduced project risk,
earlier detection of issues,
improved responsiveness.
Monitoring Through Agile Practices

Agile delivery improves monitoring through:

daily stand-ups,
sprint reviews,
retrospectives,
burndown charts,
backlog refinement.
Burndown Charts

Used to:

track remaining work,
identify bottlenecks,
monitor sprint progress,
detect delivery risks early.
Definition of Done (DoD)

A strong Definition of Done ensures quality and operational readiness.

Typical criteria include:

code builds successfully,
unit tests pass,
deployment completed,
documentation updated,
acceptance criteria satisfied,
peer review completed.

This helps maintain:

reliability,
maintainability,
deployment consistency.

Descriptive Analytics

Focuses on:

“What happened?”

Examples:

HR performance reporting,
operational KPIs.

Agile helps descriptive analytics because:

Focuses on:

“What is likely to happen?”

Examples:

retention prediction,
workforce trend analysis,
forecasting behaviour patterns.

Predictive systems require:

rapid experimentation,
iterative model refinement,
continuous feedback loops.

This is why Agile aligns well with data science.

Prescriptive Analytics

Focuses on:

“What should we do next?”

Examples:

staffing strategies,
retention interventions,
operational optimisation.

The “test and learn” mindset supports:

evidence-based decisions,
continuous experimentation,
reduction of uncertainty.
MVP Thinking

The Minimum Viable Product (MVP) approach focuses on:

delivering minimum useful functionality,
gathering feedback quickly,
validating assumptions,
reducing wasted effort.

Benefits:

faster time-to-market,
reduced cost,
lower project risk.
